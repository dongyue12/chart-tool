# 思维导图工具 · 全新界面设计方案

> 设计对象：WorkBuddy 思维导图梳理工具（mindmap/）
> 设计目标：美观、易用、符合用户既有习惯（对标 XMind / MindNode 的心智模型）
> 版本：v1.0 · 2026-10-24

---

## 一、设计原则

| # | 原则 | 含义 |
| --- | --- | --- |
| 1 | 画布即主角 | 导图内容占 ≥70% 视觉面积，工具栏弱化为单行、可收纳；一切非必要元素退后 |
| 2 | 按使用频率分层收纳 | 高频操作（加节点/改文字）零成本直达；中频（换颜色/优先级）放属性面板；低频（导入导出/主题）进菜单 |
| 3 | 颜色承载结构语义 | 颜色不是装饰，而是分支归属的视觉编码——同一分支同色，一眼看清结构 |
| 4 | 就近反馈 | 每个操作在 200ms 内给出可见反馈（选中环、拖拽高亮、保存状态角标） |
| 5 | 键盘优先 | Tab/Enter/F2/Delete 全流程可脱鼠标完成，符合效率工具用户习惯 |

## 二、信息架构与布局

```
┌────────────────────────────────────────────────────────┐
│ 工具栏：品牌 | 标题 | 保存态 | 面板开关 | 视图切换 | 导出 │  54px
├──────────┬───────────────────────────────┬─────────────┤
│ 侧栏 240px│          画布（弹性）           │ 属性面板 268px│
│ 搜索      │   点阵背景 + 双侧自动布局导图    │ 文字/备注    │
│ 最近导图  │   左下：状态胶囊                │ 颜色/优先级  │
│ WorkBuddy│   右下：缩放控制                │ 完成/结构操作│
│ 协作入口  │                               │ 路径面包屑   │
└──────────┴───────────────────────────────┴─────────────┘
```

- **三栏经典结构**：用户从 XMind/MindNode 迁移零学习成本
- 侧栏与属性面板均可收起（☰ / ◨），收起后画布自动扩大
- 大纲模式为画布的整页替换视图，Markdown 双向编辑

## 三、视觉规范

### 3.1 色彩
| 用途 | 值 | 说明 |
| --- | --- | --- |
| 主色 | #3B74E8 | 中心节点、选中态、主按钮 |
| 分支色板 | 蓝 #3B74E8 / 青 #12A594 / 橙 #E8833A / 玫红 #C2477F / 紫 #7A5AE8 / 绿 #2E9B57 / 金 #D9832C / 天蓝 #3F8FD0 | 按一级分支顺序循环分配 |
| 中性色 | 文字 #1F2430 · 次要 #6B7280 · 边框 #E3E6EF | 全局统一 |
| 语义色 | 完成 #2E9B57 · 高优 #E0533D · 中优 #E8A33A · 低优 #9AA3B2 | |

### 3.2 字体与字号
- 字族：PingFang SC / Microsoft YaHei / system-ui（跟随系统，保证原生感）
- 节点文字 14px（中心主题 16px/600），行高 1.45；界面 UI 13px；辅助说明 11–12px
- 只用两档字重（400/600），层级靠字号与颜色区分，不靠加粗堆砌

### 3.3 形状与阴影
- 节点圆角 9px；卡片/面板圆角 10–16px
- 阴影只用于表达"浮起"：面板浮层 > 工具栏 > 节点投影，三级递进
- 连线用贝塞尔曲线、透明度 55%，弱于节点，避免喧宾夺主

### 3.4 点阵画布背景
24px 间距点阵 + 顶部到底部的极浅纵向渐变，暗示"无限画布"同时提供空间参照。

| 列表项 | 悬停浅灰底 + 细边框；激活项主色 50 底 + 描边 + 名称变主色加粗 |

## 五、交互设计

### 5.1 关键交互
| 操作 | 行为 |
| --- | --- |
| 新建节点 | Tab/Enter 后**立即进入就地编辑**，空节点失焦自动回收 |
| 双击节点 | 就地编辑（浮层与节点像素级对齐，含缩放补偿） |
| 拖拽 | 生成跟随光标的幽灵卡片；目标节点描边变青绿提示可放置；禁止挂到自身子树 |
| 平移缩放 | 滚轮缩放（以光标为中心）、空白拖拽平移、"适应"一键归位 |
| 外部同步 | 5s 轮询检测文件变化：无编辑自动同步并 toast 提示；有编辑仅提示不覆盖 |

### 5.2 快捷键（延续行业惯例）
Tab 子节点 · Enter 同级 · F2 编辑 · Delete 删除 · Ctrl+Z/Y 撤销重做 · Ctrl+S 保存 · Ctrl+F 搜索 · 方向键空间导航

## 六、响应式策略

| 断点 | 行为 |
| --- | --- |
| ≥1180px | 三栏完整显示 |
| <1180px | 属性面板变悬浮卡片（选中节点自动带出，右上角 × 收起） |
| <880px | 侧栏变悬浮层并默认收起；标题输入框收窄 |
| <680px | 隐藏品牌文字、保存状态文字；缩放百分比隐藏 |

### 工具栏：按实测宽度收拢（不依赖断点）

固定断点只能覆盖"常见的几档窗口宽度 + 默认系统缩放"，一旦遇到 125%/150% 缩放、
侧边 dock、多显示器不同 DPI，就会在断点之间出现挤压或裁切。因此工具栏改为**运行期实测**：

1. 每次 `resize` / 字体就绪 / 在线头像变化，先恢复全部元素，再测量 `scrollWidth`
2. 只要溢出，就收起 `data-fit` 数值最小的一项，循环到不再溢出为止
3. 每个元素的 `data-fit` 即其"保留优先级"：导出下拉 5 → 保存状态 8 → 缩放 12 →
   配色 15 → 撤销重做 20 → 面板开关 25 → 导图/大纲 30 → 新建/保存 50 →
   在线头像 55 → 标题 60；品牌与更多菜单为 `keep`，永不收起
4. 被收起的功能全部在「更多 ▾」菜单内有等价入口（视图 / 配色 / 导出 / 面板显示），
   因此收拢只是换位置，不会丢功能
5. `ResizeObserver` 观察工具栏本身，兜住滚动条出现、字体回退等非窗口宽度因素

实测结果（无头浏览器逐档验证）：1440 / 1280 / 1180 / 1024 / 900 / 800 / 700 / 600 px
各档收拢项分别是 0 / 1 / 3 / 3 / 3 / 4 / 4 / 5 项，**溢出量均为 0**。

### P3 实现说明

**历史版本时间线**（`Ctrl+H` / 更多 → 历史版本）
- 右侧 336px 抽屉，垂直时间轴：圆点 + 时间 + 相对时间（「28 分钟前」）+ 节点数
- 节点数右侧显示与当前版本的差值（`+2` 绿 / `-15` 红），一眼看出改了什么量级
- 点击某条就地展开（手风琴）：等宽字体渲染的 Markdown 大纲预览 + 「恢复此版本」「复制大纲」
- 恢复前服务端会先给当前内容存档，因此恢复本身也可反悔
- 响应式：<680px 时抽屉占满全屏，从顶部展开

**协作光标**（`/api/presence` 心跳，10 秒 TTL）
- 工具栏保存状态右侧显示在线成员头像（重叠彩色圆点，最多 4 个 + `+N`）
- 画布上用对方配色绘制箭头光标 + 名字牌，并用虚线框圈出对方选中的节点
- 光标画在独立的屏幕坐标图层（`#peerLayer`），只重绘该层，不触发整图 render，避免卡顿
- 可在「更多 → 协作光标」整体关闭，开关状态记在本地

**配色与规范**：在线成员配色复用分支八色板，保证与导图配色同一套语义；头像与名字牌使用实色 + 白色文字，
对比度 ≥4.5:1 满足 WCAG AA。

## 附：流程图 / 架构图编辑器（`/diagram/`）

在原有设计语言之上扩展出第二个画布，**同一套令牌**（主色、圆角、阴影、深色模式变量）复用到新编辑器，保证两个工具看起来是同一个产品。

### 设计取舍

| 决策 | 理由 |
| --- | --- |
| 形状面板放在左栏底部（而非顶部工具条） | 添加节点是"持续动作"，靠近画布边缘、单手可取，比每次抬头找工具条省一次视觉跳转 |
| 连线入口是节点底部的小圆点（hover/常显） | 图表的主动作是"连"，把入口固定在下边缘，符合自上而下的阅读与布线方向 |
| 连线用正交折线（先竖 → 横 → 竖）而非曲线 | 流程图读者习惯"下滑—横移—下滑"的路径；正交线在小图里噪声更低 |
| 判断节点两条出边自动标「是/否」 | 80% 的流程图判断就是二分支，省掉两次输入；多余分支不自动标，避免误导 |
| 自动布局按入度分层、同层居中 | 与思维导图双侧布局区分开：流程图是"时间轴"语义，纵向分层最直观 |
| 面板在窄屏变浮层，并让"适应画布"扣除浮层宽度 | 否则一键适应后图会被侧栏盖住——这是思维导图版曾踩过的坑，直接在设计层规避 |

### 交互一致性

沿用思维导图已固化的三个细节，避免"两套工具两种手感"：

1. 双击编排放进 `pointerdown` 里自判 500ms 内二次按下（画布会重绘，原生 `dblclick` 不可靠）；
2. 编辑浮层用**画布容器相对坐标**定位，并在事件后延后聚焦，避开浏览器默认焦点转移；
3. 工具栏仍按 `data-fit` 优先级实测收拢，功能只换位置不消失。

### 图形互转的产品语义

转换被定义为"**换个视角看同一件事**"，而不是导入导出格式：

- 导图 → 流程图：把"并列的分支"读成"顺序的步骤"，适合把发散梳理收敛成可执行流程；
- 流程图 → 导图：把"流程节点"读成"知识结构"，适合把流程沉淀成可讲解的大纲；
- 两种图共用 `id/text/note` 语义与配色规则，所以来回转换时文字、备注、层级都不会丢，只有"形状"降级为备注文字。
